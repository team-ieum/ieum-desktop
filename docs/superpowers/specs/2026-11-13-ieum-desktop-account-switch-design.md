# IEUM 데스크톱 — 기본 계정 바꾸기 + 한도 도달 시 계정 권하기

날짜: 2026-11-13 · 브랜치 `hodoon/desktop-ui-redesign`

## 왜

구독 계정(Claude·Codex)을 여러 개 연결해 두고, 한 계정이 한도에 닿으면 다른 계정으로 바꿔 쓰는 게 실제 사용 패턴이다(사용자 화면: 이 Mac의 로그인 세션 100%, 다른 계정 12%). 지금은 바꾸려면 설정 › AI 제공자 계정까지 들어가야 하고, 한도에 닿은 걸 알려 주지도 않는다. 사용량 팝오버의 계정 목록은 보기 전용이라 눌러도 반응이 없어 "클릭이 안 된다"는 느낌을 준다.

## 이미 있는 것 (바꾸지 않는다)

- **노드별 계정**: AI 노드(`local.ai`) 설정의 `credential` 칸. 비면 실행 순간의 기본 계정, 고르면 그 계정(`crates/ieum-local/src/ai/mod.rs` resolve). → 계정을 직접 고른 노드는 기본 계정 변경에 영향받지 않는다. 사용자가 원한 "노드는 설정한 계정으로"가 이미 충족된다.
- **기본 계정 변경**: `api.setDefaultCredential(kind, id)` → `set_default_credential` 명령(`credentials.rs` `set_default`). 설정 화면에서 쓰는 중.
- **구독 사용량 캐시**: `plan_usage.rs` `Cache` — 실패 시 직전 성공값 유지, 429면 `Retry-After`(60초~15분) 대기, [새로 고침]은 캐시 건너뜀(성공 직후 10초 제외).

## 목표

계정을 바꾸는 이유는 세 회사 모두 같다 — 쓰던 계정이 한도에 닿아도 다른 계정으로 계속 쓰기(사용자 결정).

1. 사용량 팝오버(두 번째 패널)의 계정 줄을 누르면 확인 창 → 기본 계정 변경. **Claude·Codex.**
2. 기본 계정이 한도에 닿고 같은 회사 다른 계정에 여유가 있으면 "바꿔서 쓸까요?"를 권한다. 앱이 앞이면 앱 안 알림 띠, 뒤면 macOS 시스템 알림. **Claude·Codex.**
3. 구독 조회 주기를 60초 → 평소 5분 / 80% 이상 2분으로 줄인다.
4. 사용량 창 표시를 Orca 수준으로: Claude 모델별 주간 창(Fable 등), Antigravity 모델 그룹별 창.

## 하지 않는 것

- 자동으로 계정을 바꾸지 않는다. 언제나 사용자가 [바꾸기]를 누른다.
- **Antigravity 계정 전환은 다음 작업(별도 설계).** 앱이 Antigravity 로그인을 하나만 알고, 여러 계정을 저장·전환하려면 `agy`의 키체인 로그인을 바꿔 끼워야 해 다른 앱의 인증을 건드린다. 이번엔 표시(목표 4)만.
- AI 노드가 한도로 실패했을 때 권하기(오류 문구 파싱 — 깨지기 쉬워 제외).
- API 키 기본 변경은 이번 범위가 아니다(팝오버엔 구독 계정만 있다).
- Codex AI 노드 실행 지원(`ai/mod.rs` "`cli:codex`는 보류")은 이번 범위가 아니다. Codex 기본 계정은 앱 안 기본값으로만 바뀐다.

## 실패로 치는 것

- 알림이 같은 상황에서 반복해서 뜬다(귀찮으면 끈다).
- 조회가 늘어 429가 더 잦아진다.
- 확인 창 문구가 "모든 노드가 바뀐다"처럼 읽혀서, 계정을 고른 노드도 바뀐다고 오해하게 만든다.

## 검토한 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| A. 앱 안 알림 띠만 | 단순, 기존 화면 조회에 얹음 | 앱을 보고 있어야 앎 |
| **B. A + 시스템 알림 (선택)** | 앱이 뒤에 있어도 앎 | 감시를 Rust 백그라운드로 옮겨야 함 |
| C. 노드 실패 시 권하기 | 실제로 막혔을 때만 | CLI 오류 문구 의존, 깨지기 쉬움 |

사용자가 B를 골랐다. 시스템 알림은 앱이 뒤에 있을 때 의미가 있으므로, 지금처럼 화면(상태 줄)이 조회하고 창이 안 보이면 멈추는 구조로는 안 된다.

## 설계

### 1. 감시 (Rust 백그라운드 작업)

- 앱 시작 시 `tauri::async_runtime::spawn`으로 루프 하나. 로그인 계정이 없으면(로그아웃) 아무것도 조회하지 않는다.
- 매 회차: Claude·Codex 각각 **기본 계정**의 사용량을 `SubscriptionUsage::get`(캐시 경유)로 읽는다. Antigravity도 같이 읽어 화면 표시용으로만 쓴다.
- 다음 회차까지: **한도 판정 대상 창**(아래 2절) 중 가장 빡빡한 것이 **80% 이상인 기본 계정이 하나라도 있으면 2분, 아니면 5분**. 429 대기는 캐시가 처리한다.
- **키체인 허용 창을 백그라운드에서 띄우지 않는다**(사용자 결정). 감시 루프는 이미 허용받아 읽은 적 있는(이번 실행에서 `Found`) 계정만 읽는다. 아직 못 읽은 계정은 권할 후보에서 빠지고, 화면에서 [새로 고침]하거나 팝오버를 열 때(앱이 앞일 때) 허용받는다. 빌더는 토큰 읽기에 "허용 창 금지" 모드(`security`를 상호작용 없이 — 실패하면 `Missing` 취급)가 가능한지 확인해 쓴다.
- 상태 줄 60초 타이머는 오늘 API 사용량(`loadToday`)만 계속 읽고 구독 조회는 뺀다.
- 결과를 이벤트(`plans-updated`, 키 = `planKey` 형식 `claude:<id>`·`codex:<id>`·`antigravity` → `PlanUsage`)로 화면에 보낸다. 상태 줄·대시보드·팝오버는 이 이벤트로 스토어(`usePlanStore`)를 채우고, **화면 쪽 60초 `setInterval` 조회는 없앤다**. 처음 열 때 한 번 읽기와 [새로 고침]은 그대로(명령 직접 호출).
- 백엔드 캐시 TTL(60초)은 그대로 둔다 — 주기는 감시 루프가 정한다.

### 2. 한도 도달 판정과 권하기

- **한도 판정 대상 창 = 모델 전용이 아닌 창만**(사용자 결정): Claude `five_hour`·`seven_day`, Codex `session`·`weekly`. Claude `seven_day_opus`·Fable 같은 모델별 창은 표시만 한다(그 모델만 막히고 다른 모델은 쓸 수 있으므로).
- 조건: 기본 계정의 판정 대상 창 중 하나가 `usedPct >= 100` **그리고** 같은 회사의 다른 계정 중 판정 대상 창이 모두 100% 미만인 계정이 있다.
- 다른 계정 사용량은 **조건의 앞부분(기본 계정 100%)이 맞을 때만** 조회한다(평소엔 기본 계정만).
- 권할 계정 = 다른 계정 중 판정 대상 창의 최댓값이 가장 낮은 것.
- 한 번만: `(회사, 기본 계정 id, 100%에 닿은 창 kind, 그 창 resetsAt)`을 "알린 것"으로 기억(메모리, 앱 재시작 시 초기화 — 재시작 후 한 번 더 뜨는 건 허용). 같은 키면 다시 권하지 않는다. "나중에"도 같은 키로 기억.
- 앱이 앞(포커스)이면 이벤트 `account-suggest`로 화면에 띠를 띄운다. 뒤면 시스템 알림을 보내고, 같은 제안을 "대기 중"으로 둔다. 알림 클릭은 기존 `notify.rs` `listen_clicks` → `open-target` 흐름을 재사용해 창을 띄우고 대기 중 제안을 띠로 보여 준다. 클릭 없이 앱으로 돌아와도(포커스) 띠를 보여 준다.
- 시스템 알림 문구(한/영, `notify.rs`의 언어 규칙): 제목 "Claude 한도에 닿았어요", 본문 "<계정 이름>(<N>% 사용)으로 바꿔서 쓸까요?". 이메일은 넣지 않고 계정 이름표(`credLabel`)를 쓴다 — 알림 센터에 남기 때문.
- 설정 › 알림에 스위치 "구독 한도 도달 시 계정 권하기"(기본 켜짐, `Settings.notify_account_suggest`). 끄면 띠·시스템 알림 둘 다 안 뜬다.

### 3. 확인 창 (팝오버 클릭과 띠 [바꾸기] 공용)

```
 기본 Claude 계정을 바꿀까요?
 이 Mac의 로그인 → ehgns79513@gmail.com (12% 사용)

 계정을 '기본'으로 둔 AI 노드는 이제 이 계정을 써요.
 계정을 직접 고른 노드는 그대로예요.
                                     [취소] [바꾸기]
```

- [바꾸기] → `api.setDefaultCredential(kind, id)` → 자격 목록 다시 읽기 → 사용량 새로 읽기.
- Codex 문구는 AI 노드 안내 대신 "IEUM에서 Codex 구독을 쓸 때 이 계정을 써요."(노드 실행이 아직 Claude만이라 노드 문구는 틀린 말이 됨).
- 이미 기본인 계정을 누르면 창을 띄우지 않는다.
- 팝오버 계정 줄은 버튼이 된다(키보드 Enter·Space, 포커스 테두리). 기본 계정 줄은 체크 표시 그대로, 누를 수 없음(`aria-disabled`).

### 4. 사용량 창 표시 (Claude 모델별·Antigravity 그룹별)

- `PlanWindow`에 선택 칸 `label`(화면에 그대로 쓰는 이름)을 더한다. 있으면 `usage.window.<kind>` 번역 대신 쓴다. 기존 kind는 그대로(초기화·판정용).
- **Claude**: 응답의 `limits` 배열에서 `kind == "weekly_scoped"`이고 `percent`가 숫자인 항목마다 창 하나(kind `seven_day_model`, label = `scope.model.display_name`, used = `percent`, resets = `resets_at`). 옛 응답 대비로 `seven_day_fable`·`fable_weekly`·`fable_seven_day` 키도 Fable로 읽는다(Orca 앱 번들에서 확인한 순서). `seven_day_opus`는 지금처럼. 같은 모델이 두 번 나오면 하나만.
- **Antigravity**: 지금 파서는 그룹을 무시하고 kind별 최댓값으로 합쳐, Argon만 100%인데 "주간 100%"로 보이는 버그가 있다. 버킷마다 창 하나, label = `"<group.name> · <bucket.name>"`(그룹에 버킷이 하나면 bucket.name만), kind는 `window`(`5h`→`session`, `weekly`→`weekly`). `disabled` 버킷은 뺀다. 실측 응답(2026-11-13): 그룹 Gemini Models(weekly·5h), Claude and GPT models(weekly·5h), Gemini 4 Argon(weekly 하나).
- 상태 줄·팝오버 첫 줄의 "가장 빡빡한 창"(`tightest`)은 지금처럼 모든 창 기준(표시용). 한도 판정만 2절 규칙.

### 5. 팝오버 대각선 이동

두 번째 패널로 마우스를 대각선으로 옮기다 다른 회사 줄을 스치면 패널이 바뀐다. 줄 `onMouseEnter`의 전환을 150ms 늦추고, 그 사이 마우스가 패널 안으로 들어가면 취소한다.

## 정해진 것 / 빌더 몫

- 정해짐(사용자): 확인 창 방식, B(띠 + 시스템 알림), 주기 5분/80% 이상 2분, 한 창이 초기화될 때까지 한 번만, 알림 스위치, Claude·Codex 포함(Antigravity 전환은 다음), 백그라운드 키체인 허용 창 금지, 모델 전용 창은 판정 제외, Fable·Antigravity 그룹별 표시.
- 빌더 몫: 띠의 위치·모양(웹 이음 색, 기존 알림 컴포넌트 재사용 우선), 이벤트 페이로드 세부, 대기 중 제안 저장 위치, 테스트 구성.
